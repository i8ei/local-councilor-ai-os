# 自治体データ取り込み・探索プレイブック（Ingestion Playbook）

自治体の議事録・例規集・予算・決算データをローカルに取り込み、AIエージェントやObsidianで活用するための実践的知見・パターン集・処方箋です。

---

## 1. 基本原則と責任境界

全国1,741基礎自治体のデータ形式（PDF、HTML、Excel、スキャン画像等）は千差万別です。すべてをOSコアで完璧に吸収しようとすると保守が破綻するため、以下の役割分担を原則とします。

```
【OSコア（共通基盤）】
 ├ 全国の公式入口カタログ（source_profiles/）
 ├ 標準データ契約・JSONスキーマ（data-contracts/）
 ├ 汎用検算・多年度分析エンジン（modules/settlement_review/）
 └ 高速・軽量な自動Scout（8並列＋Early Exit、取れる約8割を自動特定）
        │
        ▼ ［境界線：データ契約を満たすJSON/SQLiteを渡す］
        │
【ユーザー ＋ 手元のAIエージェント（個別実務）】
 ├ not_found（未検出）の自治体URLのオンデマンド手動特定
 ├ 自治体固有PDFのテキスト抽出・OCR・Excel変換
 └ 議員個人の政策課題に基づくツボ抽出・質問原稿作成
```

### ステータス語彙の厳密な定義
- **`ready`**: 人間または機械検証により、正本資料の取得・パースが確認された状態。
- **`needs_review`**: 自動Scoutにより公式ページ上またはベンダー上で入口が特定されたが、手動での中身精査前の状態（エビデンス保持）。
- **`not_found`**: **「標準探索（トップ〜2手・主要ベンダー規則）の範囲内では入口を検知できなかった（未検出）」** 状態。
  - ※「自治体がウェブ上に公開していない（非公開）」と決めつけるものではありません。深層に埋もれているか、検索窓専用か、あるいは本当に非公開なのかは、現場で必要になったタイミングで切り分けます。
- **`blocked`**: 自治体CMSの `robots.txt` によりクローラー取得が明示的に拒否された状態（手動ブラウザ取得が必要）。

## 2. 実地検証で得られた探索・検知パターン

福岡県（60）・長崎県（21）・熊本県（45）の実地Scoutから確立された検知パターンです。

### ① ポータル・スプラッシュ構造の攻略
- **観光・防災重視型ポータル**:
  - 町村部を中心に、トップページが観光情報や防災サイトになっており、行政本編への入口が `'くらし・行政'` や `default.html`, `index2.html`, `0000/index.html` に集約されているケースが多い（波佐見町、水上村、諫早市、東峰村等）。
  - **処方箋**: これらのハブリンクを **Priority 0（最優先）** でキューイングし、1手目で行政メニューを展開する。

### ② 表記ゆれ（議事録 vs 会議録）
- 自治体によって「会議録」派（会議録検索、定例会会議録等）と「議事録」派（本会議議事録、議事録・採択一覧、議事の記録等）に二分される。
- **処方箋**: 単語単体（`議事録`, `会議録`）およびURLパス（`kaigiroku`, `gijiroku`, `50400` 等）の両方でマッチングする。

### ③ 主要ベンダーと安全な逆引きプローブ
自治体トップページからリンクが消えていたり深層に埋もれていても、ベンダー側のURLは不変で生きていることが多い。

| アダプター名 | 主な提供ベンダー | URL規則 / 逆引きパターン | 安全ガードレール |
|---|---|---|---|
| `g_reiki` | ぎょうせい（例規Net） | `https://www1.g-reiki.net/<slug>/reiki_menu.html`<br>`https://www1.g-reiki.net/town.<slug>/`<br>`https://www1.g-reiki.net/vill.<slug>/` | レスポンス本文・タイトル内に**自治体名＋例規キーワード**が明記されていること |
| `d1_law` | 第一法規（D1-Law） | `https://<domain>/d1w_reiki/reiki.html`<br>`https://en3-jg.d1-law.com/<slug>/d1w_reiki/` | 自治体名＋条例キーワードの照合 |
| `kaigiroku_net` | 会議録Net | `https://ssp.kaigiroku.net/tenant/<slug>/SpTop.html`<br>`https://ssp.kaigiroku.net/tenant/<slug>/MinuteSearch.html` | 自治体名＋議会・会議録キーワードの照合 |
| `dbsr` | NTT-AT（Discuss） | `http://www.<slug>.<pref>.dbsr.jp/index.php/` | 自治体名の照合 |

## 3. 高速化と外部サーバーへの配慮（Politeness設計）

全国1,741自治体を効率的かつ安全に走破するための運用ルールです。

1. **早期打ち切り（Early Exit）**:
   - 議事録・例規・予算・決算の4分野が揃った時点で、残りのキュー探索（上限12ページ）を即座に `break`。無駄なHTTP通信を約7割削減。
2. **異なる自治体間での安全な並列化（Concurrency: 8〜10）**:
   - 並列化するのは「別々の自治体（別ドメイン）」同士。
   - **同一の自治体サーバーに対しては最低1.0秒以上のウェイト（`POLITENESS_DELAY`）を厳守**。
3. **ベンダーサーバーへのアクセス最小化**:
   - 逆引きプローブは「通常探索で取れなかった場合のフォールバック（全体の1〜2割）」のみに限定発火。

## 4. 手元AIエージェントへの指示レシピ（プロンプト集）

未特定の自治体や個別データ取り込みを手元AI（Claude Code / Antigravity / Codex 等）に委託する際の定型プロンプトです。

### レシピ 1: 未特定（`not_found`）自治体のURLを手動特定させる
```markdown
【指示】
〇〇県〇〇町の「議事録検索ページ」および「当初予算書・決算書の掲載ページ」を探してください。
自治体公式ホームページ（https://...）または公式議会ページからリンクをたどり、
一次資料（PDFまたは検索システム）のURLを特定して、source_profiles の JSON を更新してください。
推測のURLは入れず、必ず公式導線が確認できたURLのみを evidence に記録してください。
```

### レシピ 2: 予算・決算PDF/Excelからデータ契約JSONを抽出させる
```markdown
【指示】
添付の〇〇町「令和〇年度一般会計当初予算書（PDF/Excel）」から、
歳入および歳出の款・項・目・節の金額を抽出してください。
出力は data-contracts/settlement.schema.json （または budget.schema.json）に完全準拠した JSON としてください。
【厳守ルール】
1. 金額の単位（千円・円）を正確に合わせること。
2. 数字の書き写しミスがないよう、款合計と項合計の検算を自分で行うこと。
3. 不明な科目は勝手に補完せず、null または空欄とすること。
```
