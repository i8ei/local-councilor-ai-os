# EBPM質問・政策設計ワークフロー（EBPM Policy Design）

地方議員が「住民の声や勘・感情論」だけで終わらせず、**決算データ・議事録・類似団体比較のエビデンスとロジックモデル**に基づいて、行政が動かせる具体的な政策提言と質問原稿を組み立てる実務手順です。

---

## 1. 全体プロセス（4ステップ）

```text
1. エビデンス収集  [Evidence]
   ├ 多年度決算データ（不用額・未済額・執行率）の自動抽出
   ├ 議事録全文検索による過去の町長・課長答弁の照合
   └ 類似団体（同規模自治体）との指標比較
        │
        ▼
2. ロジックモデル分析 [Logic Model]
   ├ インプット（予算）とアウトプット（実績）の乖離を特定
   └ 制度・運用・周知・連携のボトルネックを解明
        │
        ▼
3. 政策提言・質問設計 [Policy Action]
   ├ 行政が動かせる具体的な変更点（予算減額、独自施策シフト、要綱改正）
   └ 議会質問（事実確認 → 改善要求 → 予算措置）の原稿化
        │
        ▼
4. アウトカム指標（検証KPI） [Outcome KPI]
   └ 翌年度の決算審査・委員会で検証すべき定量的目標を設定
```

## 2. 実務ステップ詳細

### Step 1: エビデンスの自動抽出
手元のSQLiteデータベースから、数字と過去答弁を0トークン・一瞬で引き出します。

```bash
# ① 決算データから不用額常態化・連続繰越・未収金を抽出
python3 -m modules.settlement_review.bridge --db /path/to/settlement.db --min-years 2

# ② 議事録から過去の答弁を検索
python3 -m modules.minutes_db.search --db /path/to/minutes.db --query "障害福祉 OR 給付費"
```

### Step 2: ロジックモデルによるボトルネック特定
行政の施策構造を以下の4要素に分解し、「どこで詰まっているか」を整理します。
- **インプット（投入）**: 当初予算、人員、国県町負担割合
- **アクティビティ（活動）**: 給付決定、相談対応、広報、個別通知
- **アウトプット（直接実績）**: 実受給者数、支出済額、接種率
- **ボトルネックの特定**:
  - *前年踏襲型*: 毎年同額を積んでいるが、実績が追いつかず多額の不用額が常態化
  - *周知不足型*: 制度はあるが対象者に届いておらず、申請が低迷
  - *連携不足型*: 税務課の滞納情報と企画課の空き家情報が分断

### Step 3: 政策提言・質問の組み立て
感情論ではなく、行政が翌年度予算や次期計画で実行可能なアクションを提案します。
1. **事実確認**: 過去の数字の乖離を淡々と突きつける（感情を入れない）
2. **改善要求**: ボトルネックを解消する運用改善・要綱見直しを要求
3. **予算措置**: 不用となった一般財源を、町独自の支援策へシフトするよう提案

### Step 4: アウトカム検証（次回審査のKPI）
質問しっぱなし（言いっぱなし）を防ぐため、次回決算での確認指標を記録します。
- 「翌年度決算で不用率が〇%未満に改善されたか？」
- 「独自助成の利用者が〇人増えたか？」

## 3. 手元AIエージェントへの指示プロンプト例

```markdown
【指示】
以下の決算データと議事録答弁から、templates/ebpm-question-card.md に準拠した「EBPM質問設計カード」を作成してください。
【入力データ】
- 科目: 障害福祉費
- 決算推移: 4年連続不用額（R4: 6200万, R5: 1.1億, R6: 1.3億, R7: 8400万）
- 過去答弁: 令和7年9月決算委員会 課長答弁「受給者数の見込みが過大だった...」
【出力要件】
1. インプットとアウトプットの乖離要因をロジックモデルで分析すること。
2. 拘束されている町単独財源（25%）を、在宅重度障害者支援やレスパイトケアにシフトする政策提言を盛り込むこと。
3. 次回決算で確認すべきアウトカムKPIを設定すること。
```
